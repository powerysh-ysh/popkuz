## 1. 한눈에 보기

```
관람객이 부스에 들어옴
   ↓  입구 QR(초꾸) 스캔
닉네임 입력 (가입 없음, 10초)
   ↓  부스 5곳을 돌며 QR 스캔
도감이 한 칸씩 채워짐 (못 만난 애는 회색 실루엣 + 위치 힌트)
   ↓  5마리 완성
진화형 5종 해금 + 6자리 인증 코드
   ↓  스태프에게 화면 제시
경품 수령
```

**QR 5개는 전부 우리 부스 안에 있습니다.** 관람객이 5곳을 도는 동안 팀원 전시품을
전부 보게 되는 것이 이 게임의 진짜 목적입니다.

## 4. 스태프 운영

### 안내 멘트 (입구에서)
> "부스 안에 캐릭터 5마리가 숨어 있어요. QR 찍어서 다 모으면 선물 드려요!"

닉네임 입력이 첫 관문입니다. **폰을 들고 머뭇거리는 분께는 "아무 이름이나 괜찮아요"** 한마디가
이탈을 크게 줄입니다.

### 경품 확인
관람객 화면에 **① 진화형 5종**이 보이고 **② 6자리 인증 코드**가 떠 있으면 완주입니다.

- 코드는 사람마다 다르고, **같은 사람은 항상 같은 코드**가 나옵니다
- 받아간 코드를 종이에 적어두면 중복 수령을 막을 수 있습니다
- 화면만 보여주면 되고, 스태프가 뭘 입력할 필요는 없습니다

### 자주 나올 질문
| 질문 | 답 |
|---|---|
| "가입해야 하나요?" | 아니요. 닉네임만 정하면 바로 시작합니다 |
| "앱 깔아야 하나요?" | 아니요. QR 찍으면 바로 열립니다 |
| "중간에 껐는데요" | 같은 폰·같은 브라우저면 그대로 이어집니다 |
| "다시 처음부터 하고 싶어요" | 스태프 화면에서 초기화 (관람객 폰에서는 불가) |

## 5. 실기기 테스트 (폰 1대로 충분)

`print/00-테스트시트.png` 를 A4로 뽑거나 **모니터에 띄워놓고** 폰으로 찍으면 됩니다.

1. 스태프 화면 → **진행 초기화**
2. 홈에서 닉네임 입력
3. QR 5개를 차례로 스캔 → 매번 캐릭터가 뜨는지
4. 도감에 5칸이 컬러로 채워지고 **진화형이 해금**되는지
5. **비행기모드로 전환** → 도감이 그대로 보이는지 ← 전시장 와이파이 대비
6. 인증 코드 6자리가 뜨는지

### iOS 폰이 없다면
행사 전에 **팀원 중 아이폰 쓰는 분에게 링크만 보내서** 3번까지만 확인 부탁하세요.
한 사람이 1분이면 됩니다. 9/15 회의 참석자 중에 계실 겁니다.

### ⚠️ 카카오톡으로 링크를 받아서 열면
카톡 안의 브라우저와, QR을 찍었을 때 열리는 기본 브라우저는 **저장 공간이 서로 다릅니다.**
카톡에서 모은 진행 상황은 카메라로 찍었을 때 이어지지 않습니다.

**현장에서는 전부 QR로 들어오므로 문제가 없습니다.** 다만 테스트할 때
카톡으로 링크를 열었다면, 실제 QR 스캔과는 별개로 기록된다는 점만 알아두세요.

## 6. 통계 보기

Supabase 대시보드 → SQL Editor. 쿼리 전문은 `supabase.sql` 아래쪽에 있습니다.

### 1일차 저녁에 꼭 보세요 — 2·3일차 경품 배분이 여기서 결정됩니다
```sql
select date(caught_at at time zone 'Asia/Seoul') as 날짜,
       count(distinct hunter_id) as 참여자
from hunt_catches group by 1 order by 1;
```

### 요약 (성과보고서용)
```sql
select
  (select count(*) from hunt_hunters)     as 참여자,
  (select count(*) from hunt_completions) as 완주자,
  (select count(*) from hunt_catches)     as 총획득;
```

### 동선 검증 — 유독 적게 잡힌 캐릭터 = QR이 안 보이는 위치
```sql
select character_id, count(*) from hunt_catches group by 1 order by 2 desc;
```
2일차 아침에 그 QR을 더 잘 보이는 곳으로 옮기세요.

### 테스트 기록 초기화 (9/29 세팅 때 1회)
```sql
truncate hunt_catches, hunt_completions, hunt_hunters;
```

## 7. 문제가 생기면

| 증상 | 확인 | 해결 |
|---|---|---|
| QR을 찍었는데 "여긴 아무도 없네요" | QR 카드가 최신 주소로 인쇄됐는지 | `npm run qr -- <주소>` 로 다시 인쇄 |
| 화면이 안 열림 | 폰 데이터/와이파이 | 첫 진입만 인터넷 필요. 이후는 오프라인 가능 |
| 도감이 비어 있음 | 다른 브라우저로 연 것은 아닌지 | 같은 브라우저로 다시 열기 |
| 통계가 안 쌓임 | 스태프 화면 → **쓰기 자가진단** | 아래 참고 |

### 쓰기 자가진단 읽는 법
스태프 화면 맨 아래 버튼입니다.

| 표시 | 뜻 |
|---|---|
| ✅ 저장 확인 (201 → 409 중복) | **정상.** 기록이 DB에 실제로 남고 있음 |
| ⚠️ 테이블 없음 | `supabase.sql` 미실행 |
| ⚠️ 쓰기 거부 42501 | RLS 정책 누락 → `supabase.sql` 2번 섹션 재실행 |
| — 환경변수 없음 | 통계만 꺼진 상태. **게임은 정상 작동합니다** |

> **통계가 꺼져도 게임은 멈추지 않습니다.** 기록은 관람객 폰에 먼저 저장되고
> 서버 전송은 실패해도 무시합니다. 현장에서 통계 문제로 게임을 세우지 마세요.

## 8. (선택) Netlify로 주소를 옮기고 싶다면

지금은 GitHub Pages 주소를 씁니다. 더 짧은 `popkuz.netlify.app` 으로 옮기고 싶다면:

1. Netlify의 **popkuz 프로젝트 → Project overview → Production deploys**
   드래그 영역에 `popkuz-netlify.zip` 을 올립니다
2. **`app.netlify.com/drop` 은 쓰지 마세요** — 새 프로젝트가 또 생깁니다
3. 올린 뒤 `npm run qr -- https://popkuz.netlify.app` 로 **QR을 다시 뽑아 인쇄**

> zip 안에 `netlify.toml` 이 들어 있으면 Netlify가 빌드를 시도하다 실패합니다.
> 배포용 zip에는 빌드 설정을 넣지 않습니다 (지금 zip은 제거된 상태).

**필수가 아닙니다.** 주소가 10글자 짧아지는 것 외에 차이가 없습니다.
