# 팝꾸즈를 찾아라! — 부스 스탬프랠리 기획서

> 2026 산학협력 EXPO · 킨텍스 제2전시장 · 동명대학교 창업학과 시작박스 부스
> 행사기간 2026.09.30(수) ~ 10.02(금)

---

## 1. 한 줄 요약

**부스 안에 숨은 팝꾸즈 5마리를 QR로 찾아 도감을 채우면 진화형이 해금되고 경품을 받는 게임.**

관람객 체감은 포켓몬고와 같습니다. "돌아다니며 찾아서 모은다"가 핵심이고, GPS는 실내에서 못 쓰므로 QR로 대체합니다.

---

## 2. 왜 이 방식인가

| 고려사항 | 판단 |
|---|---|
| 실내 GPS 오차 50~100m | 부스 6개 구역이 통째로 그보다 작음 → **GPS 불가** |
| WebXR / 8th Wall AR | iOS 사파리 제약 + 유료 + 학습기간 → **D-9에 불가** |
| 타 대학 부스 연계(B안) | "다른 대학 비협조적" (9/15 교수님) → **리스크** |
| **우리 부스 내 5곳(A안)** | 협조 불필요, 전시 동선과 일치 → **채택** |

### A안의 숨은 이득
스탬프랠리가 곧 **부스 동선 설계**가 됩니다. 관람객이 5개 지점을 도는 동안 팀원 전시품을 전부 보게 되고, 체험·다이어리·인스타 팔로우가 자연스럽게 경유지가 됩니다.

---

## 3. 캐릭터 ↔ 부스 지점 매칭 (초안 — 21일 회의에서 확정)

캐릭터의 속성과 배치 지점의 성격을 맞췄습니다.

| # | 캐릭터 | 속성 | 배치 지점(안) | 매칭 근거 |
|---|---|---|---|---|
| 1 | **초꾸** CHOKKU | 🌿 풀 (자연) · 새로운 시작 | **부스 입구 / 웰컴 배너** | "어디든 가보자!" — 첫 만남 지점 |
| 2 | **빠꾸** PPAKKU | 🔥 불 (열정) · 도전 | **참가팀 전시품 존 A** | 도전하는 창업팀 제품 |
| 3 | **노꾸** NOKKU | ⚡ 전기 (아이디어) | **키캡 만들기 체험 테이블** | "새로운 아이템을 만들어냄" = 체험 |
| 4 | **흰꾸** HEENKKU | ❄️ 얼음 (지식) | **학교소개 / 벽면패널** | "차분하고 신중함" = 성과·정보 |
| 5 | **꿈꾸** KKUMKKU | ⭐ 꿈 (상상) | **시작박스 다이어리 존** | "상상을 현실로" = 웹다이어리 |

> ⚠️ 전시품 최종 목록이 확정되면 `src/data/characters.js`의 `spot` 값만 수정하면 됩니다. 코드 변경 불필요.

### 동선 의도
```
입구(초꾸) → 전시품(빠꾸) → 체험 테이블(노꾸) → 패널(흰꾸) → 다이어리(꿈꾸) → 경품
     ↑ 유입                    ↑ 체류시간 확보        ↑ 성과 노출      ↑ 인스타/사진
```
5번째 지점을 다이어리 존에 둔 이유: 완주 직전에 세우면 다이어리 작성·사진 촬영 전환율이 올라갑니다.

## 4. 게임 규칙

1. **로그인 없음.** 닉네임만 입력하고 시작. (회원가입 요구 시 이탈률 급증)
2. QR을 찍으면 해당 캐릭터 **획득 연출** → 도감에 등록
3. 5마리를 모두 모으면 → **진화형 5종 해금** (그린박꾸 / 레드박꾸 / 골드박꾸 / 스노우박꾸 / 드림박꾸)
4. 완주 화면에 **인증 코드** 표시 → 스태프에게 보여주고 경품 수령
5. 같은 QR 재스캔 시 "이미 만난 친구" 안내 (중복 방지)

### 진화형을 완주 보상으로 쓰는 이유
추가 제작비 0원인데 "숨겨진 2페이지"라는 강력한 완주 동기가 생깁니다. 포스터에 이미 진화형이 있으니 관람객이 "저것도 모을 수 있나?" 하고 먼저 물어봅니다.

## 5. 기술 설계

**스택:** React + Vite + React Router (기존 start-box와 동일) · Netlify 배포

### 핵심 설계 원칙 3가지

**① 오프라인 우선 (Offline-first)**
전시장 와이파이는 거의 확실히 죽습니다. 획득 기록은 **localStorage에 먼저 저장**하고, 서버 동기화는 실패해도 무시(best-effort)합니다. 네트워크가 끊겨도 도감은 정상 작동합니다.

**② 서버 없이도 완전 동작**
Supabase 연결은 **선택 사항**입니다. 환경변수를 안 넣어도 게임은 100% 돌아갑니다. 통계가 필요하면 나중에 켜면 됩니다.

**③ 캐릭터는 인라인 SVG**
이미지 파일 의존성 제로. 포스터 디자인을 SVG로 구현해서 로딩이 즉시 끝나고 오프라인에서도 깨지지 않습니다. 나중에 진짜 PNG가 준비되면 교체 가능.

### 화면 구성
| 경로 | 화면 | 용도 |
|---|---|---|
| `/` | 홈 | 닉네임 입력, 진행률, 게임 설명 |
| `/c/:id?k=토큰` | 획득 | QR 스캔 착지 지점, 획득 연출 |
| `/dex` | 도감 | 5칸 + 진화형 5칸 |
| `/done` | 완주 | 인증 코드 표시 |
| `/staff` | 스태프 | 완주 코드 확인 (부스 운영용) |

### 간이 부정방지
QR URL에 캐릭터별 토큰(`?k=`)을 넣어 주소 추측을 막습니다. 링크 공유까지는 막지 않습니다 — 경품 물량이 소량이면 실익이 없고, 검증 로직이 복잡해지면 현장에서 사고가 납니다.

## 8. 성과 지표 (사후 보고서용)

Supabase를 연결하면 자동 집계됩니다. 엑스포 성과보고서에 그대로 들어갑니다.

- 총 참여자 수 / 완주자 수 / 완주율
- 일자별·시간대별 참여 추이 → **어느 시간대에 인원을 더 배치해야 하는지**
- 캐릭터별 획득 수 → **어느 전시 지점이 안 읽혔는지** (동선 검증)

> 3일차 아침에 1~2일차 데이터를 보고 QR 위치를 옮길 수 있습니다.

## 9. 확장 (여유 있으면)

**AR 포토부스** — 진짜 AR이 아니라 카메라 화면 위에 캐릭터를 올려 같이 사진 찍기(`getUserMedia` + CSS 오버레이, 반나절). 찍은 사진이 시작박스 PHOTO LOG로 유입되어 웹다이어리가 실시간으로 채워집니다. 9/15 회의에서 나온 "전 과정을 웹다이어리로 현장 작성·전시" 아이디어와 직결됩니다.
